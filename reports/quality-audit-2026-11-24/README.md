# 자동 음성 검수 기록 — 2026-11-24

Qwen3-TTS 1.7B CustomVoice / Ryan이 만든 실제 음성 16개에 독립 ASR과 음향 수치 분석을 적용했습니다. **직접 청취, 사람의 감정·악센트 판정, MOS 평가는 하지 않았습니다.**

## 대상과 증거

- `001`의 6개 상황 × 2개 요청 악센트: 12개.
- `002`~`005`의 Documentary / American: 4개.
- 원음 16개와 최종 합성본 16개, 총 32개 WAV. 배경이 없는 8개는 원음과 최종본의 내용이 같습니다.
- [WAV와 생성 메타데이터](../../examples/quality-audit/README.md), [모든 전사와 측정값](samples.csv), [기계 판독용 결과](audit.json), [생성 시간 기록](generation-timing.json).

기존 샘플 4개는 변경 없이 재사용했고 12개를 새로 생성했습니다. 생성은 CPU float32 / eager attention / PyTorch 4 threads / `max_new_tokens=512`였습니다. 새 배치의 총 시간은 약 250.8초였고, 모델 로드 이후 신규 샘플은 약 13.3~21.7초씩 걸렸습니다. 이 시간에는 최초 모델 다운로드가 포함되지 않으며 다른 PC의 속도를 보장하지 않습니다. 각 WAV의 SHA256이 보고서에 들어 있어 어떤 파일을 검사했는지 확인할 수 있습니다.

## 방법

1. **독립 전사:** `faster-whisper==1.2.1`, `small.en`, CPU INT8, 2 threads, beam size 5, temperature 0. 음성은 SoundFile로 읽어 `scipy.signal.resample_poly`로 16 kHz에 맞췄습니다. 정답 문장, 상황, 요청 악센트, TTS 지시는 전달하지 않았습니다. `initial_prompt=None`, `hotwords=None`, VAD와 이전 문맥 조건도 끕니다.
2. **내용 비교:** 소문자화, 구두점 제외, `0`~`20` 숫자 표기를 단어로 정규화한 후 Levenshtein 단어 편집 거리를 계산합니다. `WER=(대체+삭제+삽입)/원문 단어 수`이며 값이 1보다 클 수도 있습니다. 각 원음/최종본 집합의 원문 단어 수 합은 127개입니다.
3. **파형 확인:** mono·sample rate·길이·유한 값·peak와 `abs(sample)>=1`의 개수를 확인합니다. 저장된 깨끗한 음성에 기록된 `mix_gain`을 곱해 합성본의 발화 구간에서 빼고 배경 성분을 복원합니다. 복원한 배경과 음성의 RMS로 SNR을 다시 계산하므로 메타데이터 숫자를 그대로 믿는 검사는 아닙니다.
4. **발화의 수치적 차이:** 전체 파형 길이와 예상 단어 수/길이를 구합니다. pYIN은 16 kHz, 1024-sample frame, 160-sample hop, 60~500 Hz 범위를 사용합니다. 유효한 F0의 중앙값과 10~90 percentile 폭을 반음 단위로 기록합니다. pitch 추정 오차가 있을 수 있고 감정·악센트 분류에 사용하지 않습니다.

## 결과와 해석

| 항목 | 결과 |
| --- | --- |
| 실제 생성 | 16/16 성공 |
| 원음 | 16/16 원문 일치, corpus WER 0% |
| 최종 합성본 | 16/16 원문 일치, corpus WER 0% |
| 디지털 클리핑 | 모든 32개 WAV에서 0개 |
| 배경 포함 8개 | 10/20 dB 목표 대비 최대 절대 오차 약 `2.4e-8 dB` |

정규화 후의 일치이며, ASR 자체가 실수를 하거나 문맥으로 음성을 보정할 수 있습니다. 따라서 ‘모든 단어의 발음이 완벽하다’는 결론은 내리지 않습니다.

`001`에서 Reassuring의 길이는 American/British 각각 3.20/3.12초로 Documentary의 2.40/2.32초보다 길었습니다. 반면 Urgent는 2.40/2.72초로 더 빠르다는 기대가 일관되게 나타나지 않았습니다. **프롬프트는 속도·감정의 강제 제약이 아닙니다.** 각 조건의 seed도 다르므로 차이의 원인을 프롬프트만으로 단정할 수 없습니다.

이 결과로 뒷받침할 수 있는 것은 ‘이번 샘플에서 내용 전사와 배경 합성 파이프라인이 동작했다’는 점입니다. 자연스러움, 상황 표현의 적절성, American/British의 정확성, 동일 화자 정체성 유지, 실제 환경의 소음 재현은 검증하지 않았습니다. 기본 10/20 dB 절차적 배경만 사용했으며, 5 dB와 실제 장소 녹음·Aiden·긴 문장·전체 60개 실제 음성으로 일반화할 수 없습니다.

## 재실행

[README의 자동 검수 명령](../../README.md#자동-검수-재실행)을 사용합니다. `audit.json`에는 설정·패키지 버전·파일 해시·전체 전사가 기록됩니다. 인식 모델의 원격 revision과 모든 플랫폼 요소를 고정한 것은 아니므로 다른 환경의 수치가 완전히 동일하다고 보장하지 않습니다. 수동 검수의 `reviews.csv`와 자동 측정 결과는 별도 파일입니다.
